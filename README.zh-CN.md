# 轻传 LanTransfer

轻量的 Windows 局域网文件互传工具。支持同一子网和网线直连，两端都运行 `LanTransfer.exe`。不依赖互联网、账户、服务器或浏览器，不会调用外部中继。

## 运行

- 目标系统：Windows 7 SP1 / 8.1 / 10 / 11，x86 和 x64。
- 需要 **.NET Framework 4.x**（不是 .NET 9）。Win7 未安装时推荐安装适用于 Win7 的 .NET Framework 4.8；Windows 10/11 通常已带运行时。
- `release/LanTransfer.exe` 和同目录的 `LanTransfer.exe.config` 一起复制到两台电脑，即可运行，无需安装应用。

## 使用

1. 接收方选择保存目录，点击「开始接收」，把本机 IPv4 和接收码告诉发送方。
2. 发送方添加文件/文件夹，也可拖入。输入对方 IPv4，或点击「搜索设备」，填入对方接收码，点击「开始发送」。
3. 首次运行如有防火墙提示，允许专用网络访问。优先使用 TCP 45871 传输；端口被占用或系统禁止绑定时，自动选择可用端口，并更新接收端界面。搜索设备会获取实际端口；手动连接时请填写接收端显示的端口。UDP 37951–37958 用于设备搜索，自动避开被占用的搜索端口。不需要关闭整个防火墙。
4. 传输中断后保留接收目录及其中的 `.lantransfer-cache`，重新发送**同一批原文件**到同一接收目录即可续传。已完整传好的文件会校验后跳过。修改后的源文件视为新文件。
5. 同名但内容不同的文件会报冲突并跳过，其他文件继续传输。需要更换接收目录或先重命名已有文件。
6. 「暂停发送」关闭当前连接。「停止接收」也会中断当前接收，未完成内容保留。双向互传时双方分别开启接收。

## 网线直连

连接两台电脑后，确保双方 IPv4 同网段。例如有线网卡分别设置 `192.168.50.1` 和 `192.168.50.2`，子网掩码 `255.255.255.0`，直连网卡的网关和 DNS 可留空。选择不与现有网络冲突的网段。软件不会自动修改网络设置。发送到对方**有线网卡**的 IP。

## 实现与边界

v0.2.1 风格统一：收发界面共用紫色主色、圆角按钮与卡片，文本框、下拉框和端口框使用等高输入外壳；进度条沿用主色，文件与文件夹改用统一的线稿图标。

v0.2.0 界面优化：发送与接收使用双栏卡片，队列可查看完整文件路径；本机 IPv4 支持下拉选择，并可复制地址与实际接收端口。收发状态独立显示，活动记录集中呈现。修复搜索结果未正确带入端口、设备搜索与发送按钮状态冲突，以及停止接收后旧进度覆盖状态的问题。小窗口仍保持双栏布局。

v0.1.1 修复：接收端口冲突时自动换用可用端口，界面同步实际端口，设备搜索支持多个候选 UDP 端口。新旧版本的文件传输协议兼容，但建议双方都使用新版本，以发现更换搜索端口后的设备。

- 原生 WinForms 界面，AnyCPU 单一可执行文件，不包含 Electron/WebView 或第三方运行库。
- 单连接按文件顺序传输，1 MiB 流式缓冲，逐目录扫描，不把整批文件内容装入内存。
- 预计算源文件 SHA-256，接收端校验部分文件前缀后恢复，接收完成再次校验 SHA-256，成功后才移动为最终文件。保留文件最后修改时间、目录结构和空目录。
- 完整性优先：首次发送会先完整读取源文件，完成后接收端也会完整读取校验；续传要扫描已接收的前缀。哈希阶段受硬盘速度影响，不显示为网络速度。
- 接收码通过随机挑战 HMAC-SHA256 验证，**文件内容不加密**；仅面向可信的局域网/直连链路，不提供互联网穿透或端口暴露功能。接收开启期间，持有接收码的设备可直接写入选定目录。
- 默认同一接收器一次处理一个发送连接。海量小文件吞吐受磁盘和每文件校验影响；当前无小文件打包、多连接并行或性能保证。
- 接收临时文件位于 `.lantransfer-cache`。清除此目录会丢失未完成文件的续传进度；不要在接收时修改目标目录或临时文件。
- 不传符号链接/目录联接，不复制 ACL、备用数据流、硬链接关系、稀疏属性等。Win7/Framework 传统路径长度限制仍适用；超长路径请缩短源/目标目录。源文件如果无法读取会终止本次发送，可修正后重试。
- 大于 4 GiB 的文件请使用 NTFS/exFAT 等支持该大小的目标文件系统；FAT32 不支持。
- 所示进度和剩余时间为当前文件；不是整批精确 ETA。文件大小使用 64 位整数。

## 构建与测试

无需 NuGet；构建机需要 .NET Framework 4.x 编译器和 .NET Framework 4.0 引用程序集（仅开发需要，用户运行不需要）。构建时使用 `/nostdlib+` 和 4.0 引用程序集，防止误用较新框架 API。在 Windows PowerShell 运行：

```powershell
# 构建程序
powershell -ExecutionPolicy Bypass -File .\build.ps1
# 构建并运行传输测试及界面检查
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test
# 构建并单独运行界面渲染检查
powershell -ExecutionPolicy Bypass -File .\build.ps1 -UiTest
# 可选：增加真实超过 4 GiB 文件传输测试，需要约 9 GiB 空闲空间
powershell -ExecutionPolicy Bypass -File .\build.ps1 -LargeTest
# 将新版本生成到独立目录，避免覆盖正在运行的程序
powershell -ExecutionPolicy Bypass -File .\build.ps1 -OutputDirectory release\v0.2.1
```

如果构建机没有 4.0 引用程序集，可在 PowerShell 5+ 运行 `powershell -ExecutionPolicy Bypass -File .\prepare-references.ps1`，从 NuGet 下载微软 `Microsoft.NETFramework.ReferenceAssemblies.net40` 1.0.3。这只用于构建，不会添加应用运行依赖。

自动化测试覆盖批量/中文路径/空目录/空文件、重复跳过、冲突保护、错误接收码、连接中断续传、损坏前缀重传、路径逃逸及协议长度限制。`-Test` 也会执行界面检查；`-UiTest` 可单独运行界面渲染检查。实际吞吐和跨机器防火墙/网线环境需要在目标设备验证。

## 源码结构

```text
src/                    Windows 桌面界面与 TCP 传输核心
tests/                  传输行为测试与界面渲染检查
build.ps1               本地构建与测试入口
prepare-references.ps1  下载构建用的微软引用程序集
```

本仓库仅包含源码和文档。编译产物、测试数据、缓存和第三方运行库安装包不提交到仓库。首次构建若缺少引用程序集，需要联网运行 `prepare-references.ps1`；引用程序集准备好后，可离线构建。

## 跨平台支持

当前只有 Windows 客户端已实现。macOS、Linux、Android、iOS 可以通过新增跨平台客户端逐步支持，但现有 WinForms 程序不能直接运行到这些平台。计划保留 Win7 兼容版，未来评估现代 .NET + Avalonia 客户端并复用传输协议；目前尚未提供其他平台的客户端或验证结果。详见[跨平台支持评估](docs/PLATFORM-SUPPORT.md)。
